# 演示工作区与交互升级

更新日期：2026-10-25。

## 如何体验

1. 打开网页，点击“体验完整示例”。账户部署中也可以在登录页点击“先体验完整示例”。
2. 看到本批 30 条中文合成评价的总结、主题和图表。点击“查看相关评价”或图表某一项，在页面下方核对对应原文。
3. 点击“围绕这些评价提问”可预填问题，不会发送请求。上方概览保持整批统计；当前关注范围会明确显示，提问也会写明关注对象。
4. 在“问 Agent”中依次点击“回放第一轮”和“继续回放第二轮”。两轮内容是明确标注的离线预置回放，数字由示例实际记录计算，并能核对两批原文。
5. 在回答下点击“加入经营简报”，再到“明细与下载”下载包含回答、图表、分母说明与原文的离线 HTML。相同问题再次加入时使用用户最新选择的回答。
6. 要自由提问，登录后明确点击“保存示例并进入实时问答”。这一步仅向自己的工作区导入两批合成评价与预置标签，不调用模型。随后勾选数据使用同意并点击“向 Agent 提问”才产生真实模型请求。

原有“查看公开英文样例”入口保留，用于展示此前公开真实评价的已保存结果。它与中文合成场景、真实用户历史分开。

## 已实现内容

| 能力 | 实现与边界 |
| --- | --- |
| 完整示例工作区 | 两批各 30 条，内置原文、预置标签、日期与产品维度、两轮回放、可下载 Excel；始终标明合成来源 |
| 安全导入 | POST `/api/v1/demo-workspace` 仅导入固定内置数据，沿用账户鉴权与工作区隔离；重复导入复用结果，保留对话 |
| 图表下钻 | 情感、主类别、差评类别、优先级与分组支持点击查看原文；主题也可选择，支持清除和重新选择 |
| 推荐追问 | 基于实际主题、分组和已选择的历史批次推荐最多三个问题；点击只填入编辑框 |
| 回答图表 | 支持整批情感、类别、分组差评占比、具体主题和选定上批情感比较，最多两图 |
| 统计可信度 | 模型只能选择受限图表规格；数值由授权报告的实际记录计算，标题和分母明确标整批范围；不接收任意代码、数值或额外批次 ID |
| 稳定主题 | 固定、可审计的中英文同义映射；保留原主题与证据，同一原记录在一个归一主题下最多计一次；认可、问题和需求分开 |
| 历史兼容 | 旧报告保留旧统计口径；主题映射版本不同时不计算主题变化，基础分类比较仍可用；旧对话缺少 charts 字段时默认空列表 |
| 经营简报 | 最多十个所选回答；重新核对报告指纹和本批/上批引用，按报告重算图表，HTML 转义、固定 SVG、无外部资源和脚本 |
| 等待反馈 | 后台任务保留原有三秒自动刷新；本地问答可显示实际模型/工具阶段。API 模式显示提交、等待、实际返回工具和总耗时，不伪装服务端流式推理 |
| 首次访问 | 无需登录可查看固定合成示例；这条路径不读取账户历史、业务原件或对话 |

## 演示顺序

建议用三分钟展示一个问题：进入示例，定位“配送时效”，点击查看相关原文；回放第一轮与第二轮，查看商品集中情况和上批引用；将回答加入经营简报并下载。实时演示可以在导入后选择少量问题，其余展示已经保存的结果。

两批示例并非真实经营数据，差异不证明某项措施产生效果。公开真实数据没有的门店、日期等字段没有被补造；历史实验和原请求预算不变。本轮开发验收使用离线 fixture 与 Mock，未执行新的真实模型请求；新图表规格尚未做真实供应商兼容性验收。

## 维护入口

- `core/demo_workspace.py` 与 `core/demo_data/reviews.json`：唯一权威示例和幂等导入。
- `core/report_interactions.py`：图表选择、原文下钻和推荐问题。
- `core/agent_charts.py`、`core/analysis_agent.py`：受限图表与真实阶段回调。
- `core/topic_taxonomy.py`、`core/review_topics.py`：主题映射、版本与计数。
- `core/agent_brief.py`：可携带的离线经营简报。
- `app.py`：展示与明确提交，保留既有三个主标签。

Docker 镜像包含整个应用；wheel 也包含 `core/demo_data/*.json`，API 导入示例不依赖源码工作目录。发布包采用显式白名单，不包含 `.env`、账户凭据、数据卷、原始用户表格或个人简历。

验证证据见 `validation/demo_upgrade_verification.json`、浏览器验收记录及对应测试日志。
