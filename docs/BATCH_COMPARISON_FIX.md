# 历史批次比较修复（2026-10-23）

修复对象：同一个工作簿的“评价1-100”和“评价101-200”已分别分析，但旧界面因为主题覆盖不足而隐藏全部比较。

## 根因与行为

本批有 97 条有效分析，97 条均有具体主题；上批有 93 条有效分析，但其中仅 92 条有具体主题。两批的主题版本和分析规则相同。原比较函数把主题覆盖是否完整作为全部指标的总开关，导致一条评价缺少主题时，情感、类别、优先级等已经存在的统计也无法显示。原界面的“统计口径不同”没有准确区分这个情况。

现在将两个判断分开：

- **基础比较**从持久化的有效逐行标签重新计数，展示两批样本量、有效覆盖率、情感、主类别和优先级的条数、占比及百分点差。明确复用的原记录保留各自统计权重；缺失或不兼容的标签、不能核对的样本数不按零补齐。
- **主题比较**保留版本、规则和覆盖检查。上批缺少主题时仅暂停具体主题增减，说明具体原因，不把未提取的主题当作没有出现，也不为了消除提示而重跑模型。
- **Agent**的 `compare_history` 分别返回基础和主题可比性，可以引用基础差异；主题不可比时不生成主题增减结论。历史原文查询仍按明确选定的批次限定。
- **报告下载**通过 HTML 导出接口的可选 `comparison_id` 带入当前选定的上批。服务端校验两份报告属于同一认证工作区，拒绝自比较；CSV 和原件不接受比较参数。
- **批次选择**显示工作表名称，方便识别同一工作簿中的不同批次。无评价日期时标明这是两次导入的差异，不推断时间趋势或经营措施的效果。

## 使用

刷新 <http://localhost:8501>，登录后从历史中打开“评价101-200”，在“与历史批次比较”中选择“评价1-100”。无需再次点击分析。选择比较后，完整 HTML 下载会同时包含比较表；Agent 也可按这个范围继续回答。

修复部署会更新页面进程，可能需要重新登录；已有原件、报告和后台结果不重新生成。
