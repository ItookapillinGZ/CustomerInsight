# CustomerInsight：Python 后端升级路线

## 目标与现有基础

将现有的客户评价分析工作台逐步升级为可独立调用、可恢复任务、按用户隔离数据的 Python 后端。选型沿用 Python：FastAPI、Pydantic、Celery、Redis、PostgreSQL、SQLAlchemy、Alembic、Docker。每一阶段围绕实际业务问题交付，技术栈名称不作为完成标准。

规划起点的业务层具备 Excel/CSV 解析、分组合并模型调用、结构校验、报告与主题统计、Agent 原文查询、多轮对话、本地历史和请求预算；当时页面直接调用 `core/` 服务。阶段一新增独立 HTTP API，阶段二新增 Redis/Celery、任务 SQLite、Outbox、检查点与网页队列入口。阶段三新增 PostgreSQL、SQLAlchemy、Alembic 及账户工作区，详见[账户服务说明](API_PHASE3.md)及[实际交付](API_PHASE3_DELIVERY.md)。全局额度仍保留原 SQLite 台账，单机和后续工作边界以当前交付为准。

用户已对 500 条评价文件中选定的一张 100 条工作表执行分析，其余四张工作表尚未分析。现有结果作为已有资产保留；具体有效覆盖与失败数量以保存报告为准。新增 API 不重跑已处理评价，不自动分析剩余 400 条，不更改历史实验、参考标签或原有 `.env` 中的模型配置。已归档结果可从历史接口读取；若结果只在旧页面内存中而未归档，需要单独确认归档情况，不能声称已迁移。

## 阶段一：独立 HTTP API

目的：让报告、原件和 Agent 能被其他客户端访问，建立清晰且可验证的请求契约。

交付内容：

- 新增独立 FastAPI 服务，复用现有解析、分析、历史与 Agent 逻辑；避免复制 Prompt 或重新实现分类流程。
- 提供健康检查、OpenAPI 文档、上传预览、同步分析、历史列表与报告读取、报告和原件下载、多轮 Agent 对话接口。协议元信息可公开查看，业务数据接口必须鉴权。
- 对请求模型、文件大小、选列、标识符和错误响应做边界校验。限制枚举与请求参数范围，不能让客户端选择任意本机路径或任意 SQL。
- 以部署者配置的 Bearer Token 保护工作区接口。此时是一个可信共享工作区，Token 不能视为账户体系或用户级授权。
- 复用原有历史存储与调用预算，沿用 `APP_DATA_DIR` 配置与既有数据库结构。需要访问旧历史时核对宿主或容器内的实际目录及卷挂载，不能静默生成另一个空工作区后声称数据已迁移；自动化测试另用临时目录。
- 提供独立启动方式、OpenAPI 契约、离线接口测试和使用文档。原 Streamlit 页面继续按现有方式使用，不声称已改为调用 API。

验收条件：

1. 无 Token 或 Token 错误时不能上传、读取历史、下载原件或调用 Agent。
2. 上传预览与读取已有历史不产生模型请求；错误工作表、错误选列、过大文件和不存在的历史返回稳定错误。
3. 在临时目录及 Mock 模型下，验证上传、同步分析、历史重开、下载和两轮追问；不读取私人原表，不修改实际归档。
4. API 进程可独立启动，通过健康检查，并能输出实际契约。

本阶段明确限制：同步分析期间 HTTP 请求保持打开；断开连接、进程退出或服务重启后不保证任务完成。没有后台任务 ID、持久队列、断点恢复、账户隔离或跨进程全局并发控制。单表行数与业务额度沿用当前配置，不为了演示直接放开为无限量。接口有了并不代表原页面已与后端完成迁移。

## 阶段二：持久化异步分析任务

目的：用户提交较大表格后获得任务 ID，关闭页面仍能继续处理，并且能查看进度和恢复未完成分组。

建议组合：FastAPI + Celery Worker + Redis，任务及分组状态以关系数据库为准；Redis 用于队列和共享限流，不把 Redis 结果缓存作为唯一业务记录。数据库可先沿用 SQLite 支持单机演示，部署多 Worker 或做并发验收前进入阶段三的 PostgreSQL 方案。

数据与状态设计：

- `analysis_jobs`：创建者范围、上传引用、字段映射、分析规则版本、请求预算、状态、进度、取消标记及时间。
- `analysis_groups`：任务、稳定分组编号、输入摘要、状态、尝试次数、租约期限及错误；任务与分组编号建立唯一约束。
- `analysis_results`：原始行定位、输出结构、模型与规则版本、实际 token usage，能够组合成现有报告。
- 状态至少包含排队、运行、部分成功、成功、失败、取消；每次合法迁移通过事务控制。API 返回 `202 Accepted` 和任务定位，状态查询不触发模型。

可靠性要求：

- 创建任务与投递消息之间设置可恢复的投递记录，处理“数据库已写入但消息尚未发送”的间隙。
- Worker 领取分组时使用事务、唯一约束和租约，重复投递先检查已提交结果。不能把消息队列的重投语义写成模型调用绝对只发生一次。
- 超时可能发生在模型服务已经处理请求之后。对该类结果未知的请求保留尝试台账和费用占用，限制自动重试；明确无法仅凭本地幂等键保证上游不重复收费。
- 每个已完成分组立即保存校验后的结果；重启从缺失分组继续。收到取消请求后停止领取新分组，正在发送的模型请求可能仍完成并计费。
- 限流与每日额度在 API、多个 Worker 间共享；模型 Key 和原文不写入普通运行日志。

验收采用 Mock 500 条或更大固定输入，不重新分析用户已处理的那张工作表，也不自动调用模型分析其余 400 条：浏览器关闭后完成；Worker 中断后恢复；相同消息重复消费不重复提交结果；额度耗尽保留已完成部分；取消后不再启动新分组。真实模型兼容性测试需要单独明确调用次数，不能从既有授权推定新预算。

本阶段同时将现有页面的上传与分析入口接入任务 API，提供任务进度和历史重开，形成浏览器到 Worker 的完整流程；页面的其他查询与追问可继续逐步迁移。

## 阶段三：关系模型与账户隔离

目的：支持多个用户安全地保存、检索和比较自己的评价，并建立数据库迁移与并发能力。

建议组合：PostgreSQL + SQLAlchemy 2.x + Alembic。账户使用成熟的密码哈希方案，按部署模式选择安全 Cookie Session 或有明确过期、撤销机制的 Token。身份凭证和模型接口 Key 分离。

实施内容：

- 逐步建模用户、工作区、文件、批次、任务、评价、分析结果、会话和消息；按照实际查询建立外键、唯一约束与索引，避免为每个模型字段盲目建表。
- 所有入口从服务端认证信息取得所有者范围。批次 ID、任务 ID 或 UUID 的不可猜测性不能替代权限校验。
- 权限覆盖列表、详情、原件和报告下载、批次比较、Agent 检索原文、删除、备份和对话。跨用户对同一个文件的去重也必须保持数据隔离。
- 原文件继续存放于受控持久卷；通过存储接口管理，后续确实需要多节点或对象存储再接 S3 兼容服务。
- 设计分页上限、稳定排序与必要索引，验证大历史列表和逐行结果的查询计划。
- 提供旧 SQLite 历史的离线导入与核对工具：先备份、导入新数据库、核对批次数量和原件/结果摘要，再切换；旧库保留回退。旧共享历史必须显式指定归属，不能直接公开给全部新账户。

验收：两个账户分别创建数据，尝试替换请求 ID、跨批比较、Agent 查原文和下载均不能越权；Alembic 可从空库升级并在测试库演练回退；迁移前后已有报告数量及内容摘要一致；并发操作不丢失对话或任务结果。

## 阶段四：接口迁移收尾、可观测与交付验证

目的：让已有页面实际使用后端能力，并能说明系统性能、故障位置和部署过程。

- 页面逐步改为“上传 → 任务进度 → 报告 → 追问”的 API 客户端。恢复历史只查询数据，明确再次分析才创建新任务。
- 按请求 ID、任务 ID 和分组 ID 关联结构化日志；指标记录队列等待、分组耗时、成功率、限流、重试、token 与预算。排除原文、认证 Token 和模型 Key。
- 健康探针区分进程存活、数据库连接和 Worker/队列状态。提供数据库与原件的一致备份及恢复演练。
- CI 运行静态检查、单元测试、临时 PostgreSQL/Redis 集成测试、镜像构建；模型接口默认使用 Mock。
- 性能测试公开硬件、数据规模、模型模拟延迟、并发用户、吞吐、P50/P95、错误率与队列积压。测试 Mock 接口只能说明后端调度能力，不能宣称真实模型吞吐。
- Docker Compose 提供 API、Worker、Redis、PostgreSQL 和现有页面的部署组合，明确持久卷、初始化与升级步骤。完成单机验证后再决定是否需要分布式部署。

## 实施顺序与完成口径

先完成阶段一并形成可运行接口，再实现异步任务、故障恢复与页面任务进度，然后处理数据库与账户，最后完成其余页面接口迁移并补齐交付证据。阶段二、三的表设计需要提前协同，但不能因为提前设计就声称已交付。

现有已分析工作表的结果可以作为只读报告展示和回归样本；任务恢复及并发测试使用独立 Mock 数据和临时存储。500 条全量输入的恢复实验使用 Mock，不将未分析的 400 条当成已有模型结果。第一阶段无须再产生模型费用。

后端简历只描述当时已经实现且通过验证的内容。尚未部署的 PostgreSQL、Redis、Celery、多用户或性能数据不得提前写成项目成果。每阶段附实际测试命令、结果与限制，保留原项目作者、来源和 MIT 许可证。
