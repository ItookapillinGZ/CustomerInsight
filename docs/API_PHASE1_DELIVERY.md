# Python 后端升级第一步交付

日期：2026-10-21。

独立 FastAPI 服务已完成并在本机 Docker 启动。接口文档为 http://localhost:8000/docs，原业务页面继续使用 http://localhost:8501/。原页面容器未重启，本阶段没有迁移其调用方式。

## 完成内容

- `backend/`：独立应用工厂、请求与响应模型、上传预览、同步分析、分页历史与明细、报告和原件下载、多轮 Agent 接口。
- 业务接口使用 Bearer Token；未配置凭证时关闭业务入口。增加统一错误结构、请求编号及脱敏日志。
- 复用原解析、分组合并分析、报告、Agent 和 SQLite 历史；同文件与同字段映射优先恢复已有结果。Excel 的编码映射保持旧页面使用的 `null`，避免已有结果失配。
- 新分析和追问必须明确允许模型调用并声明请求上限；读取及下载不调用模型。同步请求中收到的已校验结果可在后续分组异常时保存。
- `compose.api.yml`：只新增 API 容器，使用原数据卷。`pyproject.toml`、`uv.lock` 和 `requirements.txt` 同步更新，wheel 包含 `backend`。
- `tools/prepare_api_access.py`：仅在未配置 API Token 时生成独立凭据，写入本机忽略提交的 `.env`，不显示令牌值。其余模型配置保持一致。

## 继续使用

打开接口文档后，点击 Authorize，输入本机 `.env` 的 `APP_API_TOKEN` 值。该值与模型 Key 不同，不要填入 URL。历史、预览和下载可直接验证；不要为了演示接口重新分析已有数据。

操作、路由、重启与鉴权说明见 [API 使用说明](API_PHASE1.md)，后续阶段见 [升级规划](BACKEND_UPGRADE_PLAN.md)。

## 本阶段边界

当前为单工作区、单 API Worker 的同步服务。Token 持有者共享该工作区；没有账户隔离。没有 Redis、Celery 或 PostgreSQL，也没有后台任务 ID、进程崩溃后的任务续跑或跨进程统一并发槽位。

下一步是持久异步任务及页面任务进度：提交返回任务 ID，将分组进度和结果写入数据库，Worker 独立处理并恢复未完成分组。该阶段先使用独立的 500 条 Mock 输入验收，不自动消耗剩余评价的模型预算。
