## 隔离性能与故障实验

一次真实 HTTP 调度基准使用 5 个账户同时提交，各 100 条合成评价，共 **500 行、50 次模拟 SDK 调用**。单 Uvicorn 进程、单 Celery prefork 子进程，每次模拟 SDK 固定等待 100 ms。应用容器各限制 2 CPU / 768 MiB，PG / Redis 各 1 CPU / 384 MiB；宿主资源可能有竞争。

| 指标 | 实测 |
| --- | --- |
| 整流程耗时（含登录、上传与提交） | 12.446 秒 |
| 整流程吞吐 | 40.175 行 / 秒 |
| 提交接口 p95（5 个样本） | 781.933 ms |
| 轮询及首次结果行读取 p95（201 个样本） | 45.978 ms |
| 任务端到端 p95（5 个样本） | 11,413.196 ms |
| 已测 HTTP 请求 | 216 次，错误 0 |
| 实际模型请求 | 0 |

在性能计时之外，真实服务完成 `/readyz` 四阶段验证：未启动 Worker / 投递器返回 503 → 两者启动返回 200 → 只强制终止隔离投递器并等待 26 秒后返回 503 → 重启后恢复 200。故障验证没有增加模拟模型请求。没有对用户正在使用的服务做故障停机测试。

以上仅衡量该条件下的应用调度。小样本 p95 是描述性统计，不能据此宣称真实 LLM 吞吐、生产容量、性能提升比例、业务准确率或 SLA。方法与复现见 [基准说明](BENCHMARK_METHOD.md)。镜像摘要与完整参数在 [基准聚合证据](../validation/backend_phase4/scheduling_benchmark.json)。
