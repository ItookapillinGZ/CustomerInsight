# CustomerInsight 顾客评价分析

当前版本 **1.7.0** 增加历史评价复盘：SQLite 和本地原件归档、具体多方面主题、选定批次对比、原件下载、备份和删除。Agent 可以查询本批主题与用户明确选择的一份历史原文。使用和数据范围见 [工作台交付说明](WORKSPACE_DELIVERY.md)。

自己部署，使用自己的模型接口。使用者只需打开网页、上传 Excel/CSV、确认评价列，即可获得情感、问题类别、优先级、摘要、门店/商品分组及可下载的 CSV/HTML 报告。

本次 1.6.0 已用固定 5 条合成评价完成两轮真实接口验收，共 **4/6 次授权请求**：模型自主检索原文、读取原表行并撰写回答。361 项离线回归及发布包 70 项核心测试通过。实际正文已做 AI 逐行复核，人工验收仍待确认；小样本结果不代表真实业务准确率。证据与限制见 [本版交付说明](REASONING_AGENT_DELIVERY.md) 和 [AI 复核记录](validation/reasoning_agent_acceptance/QUALITY_REVIEW.md)。

## 三步开始

1. 安装 Python 3.12 或3.13，将 `.env.example` 复制为 `.env`，填写自己的接口 Key、模型与地址。
2. Windows 双击 `start-local.cmd`；首次会安装锁定依赖。
3. 浏览器打开 http://localhost:8501 ，使用你自己的评价表，或页面提供的公开评价样例。

使用Docker时，先安装并启动Docker，填好 `.env` 后在本目录执行 `docker compose up -d --build`。

[完整部署说明](SELF_HOSTING.md)涵盖 Windows、Docker、局域网、自己的域名、HTTPS、访问码与请求额度；当前 1.6.0 的回答与查表能力、验证边界见 [Agent 交付说明](REASONING_AGENT_DELIVERY.md)。此前多轮对话、单轮 Agent 和合并调用的交付说明保留历史记录，当前行为以本版交付说明为准。

## 合并分析与工作台

默认每组最多10条评价、12,000字符，100条短评通常只用10次请求。长评价自动分小组；发送前展示预计请求量。每条仍有独立编号、标签、摘要和原始行追溯。每组零重试，不自动拆组补发；额度按请求扣减。

报告顶部新增“一句话总结”：有效覆盖、正负面占比、最多的差评类别和建议优先复核数量直接取自已校验结果，不增加模型调用；没有有效结果时明确显示无法判断，部分完成时说明结论范围。

报告提供“分析结果、问 Agent、明细与下载”三个入口，支持悬停图表、分组对比、原文检索、组合筛选及筛选明细下载。统计口径和运行信息放在折叠说明中。HTML 报告含同样的一句话总结、离线 SVG 图表、证据跳转与打印排版。先点击“查看示例报告”，可不调用模型体验完整结果。

## 围绕报告连续追问

上传并完成基础分析后，在“问 Agent”输入业务问题；获得回答后可以继续追问，例如“这些评价主要在说什么？”之后再问“针对刚才提到的包装，具体怎么改进？”。模型会根据当前报告与此前对话撰写回答，说明观察到的现象、简要理由和可以尝试的动作。没有差评时也可分析正面和中性原文，区分顾客认可之处与明确提出的需求。

已有报告信息足够时，Agent 可以直接回答；需要细节时，它可先检索原评价、按行号读取原表字段、统计某列，看到查询结果后再决定是否补查。支持的工具如下：

| 工具 | 用途 |
| --- | --- |
| 整体分布、分组对比 | 查询当前分类统计及已选门店/商品分组 |
| 差评原文、高优先级案例 | 定位已分类的重点评价 |
| 查看表格字段 | 确认上传表格有哪些原始列 |
| 检索原始评价 | 按关键词、情感、类别、优先级或分组找评价，包含正面和中性，支持分页 |
| 读取表格原始行 | 按原始行号读取指定列；长文本可继续读取后续片段 |
| 汇总表格字段 | 对当前表格某列做计数，返回空值和高频值 |

每轮实际使用 **1–3 次模型请求**，最多 **6 次本地只读查询**（包括初始的整体分布和字段清单）。三次是上限，系统按实际发送的请求扣减额度，开始前预留最多三次所需的空间。与基础分类共用部署者的每日请求额度。工具只能查询当前上传表格的内存快照，不读取其他文件、不联网、不执行代码，也不修改原表。选取原表列用于回答时，必要的字段与单元格也可能发送到部署者配置的模型服务。

当前会话最多展示最近 **30 轮**；模型最多参考最近 **6 轮**，每轮历史回答最多取 **2,000 字符**，合计上下文不超过 **12,000 字符**。历史只用于理解指代和背景，统计及原始行引用须来自本轮查询。程序核对引用是否属于本次查询，不能核实模型文字中的全部解释、因果或建议；建议需要结合业务判断。信息不足时，Agent 应说明缺失的具体资料或请求澄清。

结构或引用校验失败会明确提示本轮回答未生成，不用通用统计模板代替回答，也不会自动追加无限修复请求。服务错误会保留在聊天中供查看，但不进入后续模型上下文。示例报告关闭 Agent，查看示例、切换图表、筛选和下载均为零调用。

可下载每次回答或整段对话。已归档报告和对话保存在部署机器，关闭页面后可从历史打开；清空对话同步落库。切换表格或历史对比对象会校验对话范围。清除当前页面不删除历史；删除需在历史管理明确确认。

此版本没有长期记忆、联网检索或自动执行经营动作。2026-10-18 的单轮 Agent 真实兼容性验收与人工质量检查（24/25）是历史证据，不代表 1.6.0 已通过真实接口或人工质量验收。当前验证结果见 [Agent 交付说明](REASONING_AGENT_DELIVERY.md)，历史记录见 [真实接口验收](AGENT_LIVE_ACCEPTANCE.md)。

## 试用文件

- `examples/customer_reviews_template.xlsx`：中文格式模板，3条手工示例请替换为真实数据。
- `datasets/public_reviews/customer_reviews_sample.xlsx`：20条公开英文真实评价摘录与来源说明。
- `datasets/public_reviews/samples.csv`：100条固定样本，来源、许可和复现方法见同目录 `DATA_SOURCES.md`。
- `validation/public_reviews_pilot/`：已完成20次真实调用的公开样本验收证据；读报告不产生调用。

每次最多100条、5 MB；基础分析发送选中的评价文本，Agent 提问还会发送对话、统计和查询所需的原表字段。默认每日50次尝试、并发2、零重试。共享给他人时按部署说明启用访问码，公网使用HTTPS。

## 离线自检

安装后运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`，验证随包产品测试。运行 `.\.venv\Scripts\python.exe tools/test_grouped_reviews.py` 只检查20条样例与2次分组计划，不调用模型；`tools/test_reasoning_agent.py` 默认只做离线准备检查，也不调用模型。

真实小样本验收必须明确传入 `--live --max-requests 3`（一轮），或另加 `--turns 2 --max-requests 6`（两轮），并使用独立的累计额度台账；需要先获得接口使用者的调用授权。保存的自动检查只验证结构、引用与请求账本，人工质量检查单初始为待复核，不能当作回答效果已通过。旧的 `tools/test_agent_live_acceptance.py` 仅用于读取历史验收，不再支持真实调用。
